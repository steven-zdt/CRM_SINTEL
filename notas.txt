🐳 DOCKER - GESTIÓN DE CONTENEDORES
================================================================================

# Levantar todos los servicios (construir y ejecutar)
docker compose up --build
# o usando Makefile
make up

# ⚠️ ERROR COMÚN: "You're accessing the development server over HTTPS, but it only supports HTTP"
# SOLUCIÓN 1: Usar HTTP explícitamente (NO HTTPS)
# http://localhost:8000/admin/  ✅ CORRECTO
# https://localhost:8000/admin/ ❌ INCORRECTO

# SOLUCIÓN 2: Si el navegador fuerza HTTPS automáticamente:
# - Limpiar caché del navegador
# - O usar modo incógnito
# - O acceder desde http://127.0.0.1:8000/admin/

# SOLUCIÓN 3: Deshabilitar HSTS en el navegador para localhost:
# Chrome: chrome://net-internals/#hsts
# Buscar "localhost" y eliminarlo

# Levantar en segundo plano (detached)
docker compose up -d --build

# Detener todos los servicios
docker compose down

# Detener y eliminar volúmenes (CUIDADO: borra datos)
docker compose down -v
# o usando Makefile
make down

# Ver logs del servicio web
docker compose logs -f web
# o usando Makefile
make logs

# Ver logs de todos los servicios
docker compose logs -f

# Ver logs de la base de datos
docker compose logs -f db

# Ver logs de Redis
docker compose logs -f redis

# Reiniciar un servicio específico
docker compose restart web
docker compose restart db
docker compose restart redis

# Ver estado de los servicios
docker compose ps

# Acceder a shell del contenedor web
docker compose exec web bash
# o usando Makefile
make shell

# Acceder a shell de PostgreSQL
docker compose exec db psql -U sintel -d sintel

# Acceder a Redis CLI
docker compose exec redis redis-cli

🔄 BACKUP Y RESTAURACIÓN
================================================================================

# Backup de la base de datos
docker compose exec db pg_dump -U sintel sintel > backup_$(date +%Y%m%d_%H%M%S).sql

# Restaurar backup
docker compose exec -T db psql -U sintel sintel < backup.sql

# Backup solo del esquema public
docker compose exec db pg_dump -U sintel -n public sintel > backup_public.sql

# Backup de un tenant específico
docker compose exec db pg_dump -U sintel -n <schema_name> sintel > backup_tenant.sql

================================================================================
NOTAS IMPORTANTES
================================================================================

- El esquema 'public' se crea automáticamente con migrate_schemas --shared
- Los tenants se crean desde el admin o shell de Django
- El dominio del tenant debe apuntar inicialmente a 'public'
- Las migraciones de tenant se ejecutan automáticamente al crear un nuevo tenant
- Usa 'make' commands cuando esté disponible, son más cortos
- Los logs se ven en tiempo real con 'docker compose logs -f'
- Para desarrollo, el código se monta como volumen, los cambios son inmediatos
