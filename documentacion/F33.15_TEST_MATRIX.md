## Hallazgo real de Fase 1: archivo E2E deshabilitado con solapamiento de cobertura

`tests/e2e/test_facturas_workspace.py` tiene **4 tests marcados
`@pytest.mark.e2e`** pero el modulo entero esta deshabilitado via:

```python
pytest.skip(
    "E2E deshabilitado temporalmente en CI (playwright no instalado)",
    allow_module_level=True,
)
```

**La razon del skip esta desactualizada:** Playwright SI esta instalado
y en uso activo -- el archivo hermano `tests/e2e/test_workspace_facturas_forensics.py`
(mismo directorio, mismo mecanismo `page`/`live_server`) **SI colecciona
y corre** sus 2 tests sin problema.

**Solapamiento de cobertura confirmado (Fase 29 candidato, no
consolidado todavia -- solo mapeo):**

| Test deshabilitado (`test_facturas_workspace.py`) | Cobertura equivalente activa |
|---|---|
| `test_facturas_workspace_upload_xml` | `test_workspace_upload_detail_delete` (forensics) -- mismo flujo upload->detail->delete |
| `test_facturas_workspace_upload_missing_file_shows_error` | `test_workspace_upload_missing_file_shows_error` (forensics) -- mismo escenario |
| `test_facturas_workspace_view_detail` | Parcialmente cubierto (el detalle se visita dentro del flujo combinado de forensics, pero no como escenario aislado) |
| `test_facturas_workspace_delete` | Parcialmente cubierto (idem) |

**Clasificacion: LEGACY.** No se modifica en esta fase (Fase 1 es solo
mapeo). Candidato real para Fase 29 (consolidar/eliminar con
evidencia) -- 2 de 4 tests son duplicados confirmados de cobertura ya
activa, los otros 2 tienen solapamiento parcial via el flujo combinado.

## Clasificacion SLOW

No hay instrumentacion de tiempos por test en este repo (`pytest.ini`
no tiene `--durations` configurado, no hay reporte historico de
tiempos). **No se puede clasificar SLOW con evidencia real sin
ejecutar la suite con `--durations=N` primero.** Se marca como
pendiente instrumental, no se asume.

**Excepcion documentada con evidencia real (sesion previa, F33.15):**
`ConsoleAPIConsumptionTests` (dentro de `test_legacy_public_tenants_api.py`)
es SLOW por diseño -- su `setUp()` ejecuta `CREATE SCHEMA` +
migraciones completas de tenant 2 veces por test. Medicion cuantitativa
en Fase 3 (siguiente).
